# 보고서: 검증 현황

보고서를 쓸 때 항상 읽습니다(quick 포함). "## 검증 현황" 섹션의 줄을 다음 규칙으로 씁니다.

- **영역별:** 8개 영역을 항상 이 순서(security, correctness, ops, architecture, performance, tests, readability, style)로, 각각 다음 중 하나로 적습니다.
  - `발견 N건`: 이 보고서에 적은 `[S-NN]` 항목 수(검토 권장 포함)
  - `검토함·발견 없음`
  - `미검토(사유)`: 사유는 `quick`, `focus 제외` 등
  - quick에서 `--focus`가 없으면 security·correctness 외에는 `미검토(quick)`입니다. `--focus`를 준 영역은 quick이어도 검토한 것으로 적습니다.
  - `--focus a11y`면 correctness를 `검토함·발견 없음(접근성만)` 또는 `발견 N건(접근성만)`처럼 범위를 밝힙니다.
- **검토 한계:** 규칙 제외 목록과 사유, 검토 생략 목록과 사유, 목록만 확인한 binary·lfs·submodule, diff-only 여부, 원격 참조의 fetch 시점, 확인하지 못한 가정, `[WARNINGS]` 내용, 임시 디렉터리 정리 실패(있을 때 `임시 디렉터리 정리 실패: <경로>`). 목록이 길면 사유별 개수와 대표 경로 몇 개로 줄입니다.
- **`--run-tests`일 때** (자세한 문구는 `../verification/results.md`):
  - `- 실행한 검증: npm test → 성공 (종료 코드 0, 42초)`처럼 명령마다 결과(성공, 실패, 타임아웃, 정적 검사 거부와 사유)
  - `- 실행 격리: 정적 사전 필터 통과, 실행 격리는 도구 샌드박스에 의존, 격리 활성 여부는 확인하지 못함` ("읽기 전용 보장"이라고 쓰지 않음)
  - `- 전후 비교:` 추적 파일 변경, 새 untracked 파일, ignored 디렉터리 생성·삭제, refs·index 변경의 네 가지 결과와 "저장소 밖 부수 효과는 감지 범위 밖"
  - 테스트 실패와 타임아웃은 발견 항목이 아니라 여기에 적습니다.

# 보고서: 발견 없음과 변경 없음

리뷰 결과 발견이 하나도 없거나, 매니페스트가 `target_files 0`일 때 읽습니다.

## 1. 발견 없음

전체 템플릿(quick이면 축약형)을 쓰되 "발견된 문제" 섹션을 다음처럼 씁니다.

    ## 발견된 문제
    확인된 문제 없음. 이 결과가 버그가 없음을 보장하지는 않습니다.

- 요약의 발견 줄은 `발견: Critical 0 · High 0 · Medium 0 · Low 0`(생략이 있으면 괄호 포함)입니다.
- 검증 현황과 최종 평가(`- 주요 위험: 확인된 문제 없음`)는 그대로 씁니다. 억지로 지적하지 않습니다.

## 2. 변경 없음 (`target_files 0`)

요약과 "리뷰할 변경사항 없음"만 출력합니다.

    ## 리뷰 요약
    해석된 옵션: --staged --depth standard --strictness balanced --min-severity low --focus all --max-findings 20
    상태: complete
    범위: staged (HEAD 9f8e7d6 → index)
    기준: HEAD @ 9f8e7d6
    스냅샷: index (2026-10-29 21:00 수집, staged 0)
    파일: 대상 0개 · 실제 검토 0개 · 검토 생략 0개 · 규칙 제외 0개 · 참고로 읽음 0개
    의도: 없음

    리뷰할 변경사항 없음

- 적용 프로필·발견 줄과 나머지 섹션은 쓰지 않습니다.
- 규칙 제외 파일만 바뀐 경우 마지막 줄 다음에 `규칙 제외만 변경됨: pnpm-lock.yaml (lockfile)`처럼 적습니다.
- `--changes`에서 현재 브랜치가 기준 브랜치와 같고 미커밋 변경도 없으면 범위 줄에 그 사실을 적습니다.

# `architecture` — 응집도 및 아키텍처

이 영역을 검토할 때 읽습니다. 공통 원칙은 `principles.md`, 심각도·확신도 정의와 보고 규칙은 `severity.md`를 따릅니다. 각 영역 문서는 다른 영역 문서 없이 쓸 수 있게 독립적으로 작성했습니다.

## 확인 항목

- **책임 분리:** 한 함수·클래스가 입력 파싱, 비즈니스 규칙, 저장, 외부 호출을 모두 처리
- **모듈 경계·레이어:** 컨트롤러·UI에서 DB나 외부 API를 직접 호출, 하위 레이어가 상위 레이어를 import, 순환 의존
- **중복 구현:** 같은 저장소에 이미 있는 유틸·검증·클라이언트를 다시 구현(기존 위치를 근거로 인용)
- **불필요한 의존성:** 표준 라이브러리나 기존 의존성으로 충분한데 새 라이브러리 추가, 무거운 의존성을 작은 기능에 사용
- **고아 코드:** 호출되지 않는 새 함수·export, 기능 제거 후 남은 설정·플래그·라우트, 주석 처리된 코드 블록
- **공개 API 계약 변경:** HTTP 응답 필드 삭제·이름·타입 변경, 에러 형식 변경, 이벤트·메시지 스키마 변경, 라이브러리 export·CLI 옵션 변경. 하위 호환 방안(버전, 폐기 기간)이 있는지
- **확장성 구조:** 하드코딩된 분기(`if provider == "a"`)가 늘어나는 구조, 설정으로 빼야 할 정책값
- **deep에서 추가:** 변경이 의존 그래프에서 미치는 범위, 모듈 간 결합도 증가, 데이터 소유권(같은 테이블을 여러 서비스가 직접 쓰기)

## 흔한 오탐 (보고하지 않음)

- 프로젝트 구조가 의도적으로 택한 방식(AGENTS.md 등에 문서화된 레이어 규칙)을 따르는 경우
- 일회성 스크립트·마이그레이션의 단순한 구조

## 심각도 예시

판단 기준을 맞추기 위한 예시입니다. 실제 심각도는 `severity.md` 1.1절의 요소로 조정합니다.

| 심각도 | 예시 |
|---|---|
| Critical | 공개 결제 웹훅 이벤트의 스키마를 버전 없이 바꿔 모든 외부 소비자의 처리가 즉시 중단 |
| Critical | 여러 서비스가 공유하는 인증 라이브러리의 공개 함수 시그니처를 호환 없이 바꿔 배포 즉시 전 서비스 로그인 불가 |
| High | API 응답 필드명 변경(`userName` → `username`)으로 기존 클라이언트의 화면이 깨지는 회귀 |
| High | 에러 응답 형식을 바꿔 클라이언트의 오류 처리 분기가 모두 실패 |
| Medium | 컨트롤러에서 DB를 직접 조회해 서비스 계층의 권한·캐시 규칙을 우회 |
| Medium | 기존 HTTP 클라이언트 래퍼를 두고 재시도·로깅 없는 새 클라이언트를 중복 구현 |
| Low | 호출되지 않는 새 export와 주석 처리된 이전 구현이 남음 |
| Low | 작은 날짜 포맷 기능에 무거운 날짜 라이브러리 추가 |

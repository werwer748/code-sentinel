# `tests` — 테스트

이 영역을 검토할 때 읽습니다. 공통 원칙은 `principles.md`, 심각도·확신도 정의와 보고 규칙은 `severity.md`를 따릅니다. 각 영역 문서는 다른 영역 문서 없이 쓸 수 있게 독립적으로 작성했습니다.

## 확인 항목

- **핵심 시나리오 누락:** 새 기능·분기의 정상 경로 테스트가 없음
- **실패 경로 누락:** 오류 응답, 예외, 타임아웃, 권한 거부 경로 테스트 없음
- **경계값 누락:** 빈 입력, 0, 최댓값, 날짜 경계, 페이지 끝
- **회귀:** 버그 수정에 재현 테스트가 없음, 변경된 동작에 맞춰 기존 테스트를 고치지 않아 깨지거나, 반대로 기대값만 바꿔 버그를 고정함
- **실효성 낮은 테스트:** 단언이 없거나 항상 통과, 대상 코드를 모두 mock해 아무것도 검증하지 않음, 구현 세부(비공개 함수 호출 횟수)에 결합, 스냅샷만 있는 테스트
- **비활성화:** `.only`, `.skip`, `xit`, `@Ignore`, `t.Skip` 추가, 테스트 삭제
- **불안정 요인:** 현재 시각·난수·실행 순서·실제 네트워크·고정 sleep에 의존
- **테스트 이름과 내용 불일치**, 테스트 데이터에 실제 개인정보·자격증명

## 판단 기준

- "테스트가 부족하다"가 아니라 어떤 시나리오가 빠졌는지 구체적으로 적습니다.
- 변경이 작고 기존 테스트가 이미 그 경로를 덮는지 확인한 뒤 판단합니다. 확인하지 못하면 확신도를 낮춥니다.

## 심각도 예시

판단 기준을 맞추기 위한 예시입니다. 실제 심각도는 `severity.md` 1.1절의 요소로 조정합니다.

| 심각도 | 예시 |
|---|---|
| Critical | 결제·인증 테스트를 `.skip`·삭제해 CI가 핵심 경로를 검증하지 않게 되고 같은 변경에 그 경로의 버그가 있음 (원칙적으로 드묾. 실제 버그는 해당 영역으로 별도 보고) |
| Critical | 테스트가 운영 DB·운영 결제 키로 접속하도록 설정돼 CI 실행만으로 실데이터 변경 가능 |
| High | 버그 수정 변경에서 기대값만 바꿔 버그를 테스트로 고정(회귀를 정상으로 취급) |
| High | 권한 검사를 추가했지만 거부 경로 테스트가 없고 기존 테스트도 모두 관리자 계정만 사용 |
| Medium | 새 분기의 실패 경로·경계값 테스트 누락 |
| Medium | 현재 시각에 의존해 자정·월말에 실패하는 불안정한 테스트 |
| Low | `nth-child`에 의존하는 E2E 셀렉터(마크업 변경 시 깨지기 쉬움) |
| Low | 동작 단언 없이 스냅샷만 있는 컴포넌트 테스트 |

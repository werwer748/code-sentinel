# `ops` — 운영 영향

이 영역을 검토할 때 읽습니다. 공통 원칙은 `principles.md`, 심각도·확신도 정의와 보고 규칙은 `severity.md`를 따릅니다. 각 영역 문서는 다른 영역 문서 없이 쓸 수 있게 독립적으로 작성했습니다.

## 확인 항목

**환경별 동작**
- 개발·스테이징·운영에서 다르게 동작하는 분기, 하드코딩된 호스트·URL·경로
- 기능 플래그의 기본값, 운영에서 켜지는 디버그 동작

**설정 불일치**
- 새 환경변수·설정 키가 배포 설정, 예시 파일(`.env.example`), 문서, 차트 values에 반영되지 않음
- 필수 설정에 기본값도 시작 시 검증도 없어 런타임에 늦게 실패
- 설정 이름 변경 시 구 이름과의 호환 기간 없음

**장애 시 동작**
- 외부 호출에 타임아웃 없음, 무한 재시도·재시도 폭주(백오프·지터 없음)
- 의존 서비스 하나의 장애가 전체 요청 실패로 번짐(폴백, 서킷 브레이커 부재)
- 종료 신호 처리(graceful shutdown) 누락으로 진행 중 작업 유실

**데이터 유실**
- 파괴적 마이그레이션(컬럼·테이블 삭제, 타입 축소), 백업·복구 경로 없는 삭제
- 큐 메시지를 처리 전에 ack, 실패 메시지의 dead-letter 경로 없음

**배포 순서 의존**
- 스키마와 코드 중 무엇을 먼저 배포해야 하는지에 따라 실패하는 변경
- 롤링 배포 중 구버전과 신버전이 공존할 때의 호환성, 롤백 가능성
- 캐시·메시지 형식 변경이 구버전 소비자를 깨뜨림

**로그·메트릭**
- 실패 경로에 로그·메트릭이 없어 장애를 감지할 수 없음
- 반복 루프 안의 과도한 로그, 부적절한 로그 레벨, 상관 ID 누락
- 알림·대시보드가 의존하는 메트릭 이름·레이블 변경

**리소스**
- 커넥션 풀·파일 핸들·스레드 고갈, 디스크를 채우는 임시 파일, 무제한 큐

## 흔한 오탐 (보고하지 않음)

- 프레임워크나 플랫폼이 이미 제공하는 타임아웃·재시도를 코드에서 확인한 경우
- 로컬 개발 전용 스크립트의 하드코딩(운영 경로에 포함되지 않음을 확인한 경우)

## 심각도 예시

판단 기준을 맞추기 위한 예시입니다. 실제 심각도는 `severity.md` 1.1절의 요소로 조정합니다.

| 심각도 | 예시 |
|---|---|
| Critical | 운영 테이블을 삭제·재생성하는 마이그레이션이나 IaC 변경으로 데이터베이스 리소스가 교체(파괴 후 생성)됨 |
| Critical | `prevent_destroy` 해제와 함께 상태 데이터가 든 버킷·볼륨 삭제가 계획됨 |
| High | 수천만 행 테이블에 기본값이 있는 컬럼을 추가해 배포 중 장시간 쓰기 락 |
| High | 컬럼 이름 변경을 한 번에 배포해 롤링 배포 중 구버전 인스턴스가 모두 실패 |
| Medium | 외부 API 호출에 타임아웃이 없어 상대 장애 시 워커가 고갈될 수 있음 |
| Medium | 새 필수 환경변수가 배포 설정·예시 파일에 없어 다음 배포에서 기동 실패 가능 |
| Medium | 컨테이너에 리소스 제한이 없어 한 파드가 노드 메모리를 독점 가능 |
| Low | 실패 경로의 로그에 상관 ID가 빠져 추적이 불편 |
| Low | `latest` 태그 베이스 이미지(재현성 저하, 당장 장애는 아님) |

# `style` — 스타일 및 컨벤션

이 영역을 검토할 때 읽습니다. 공통 원칙은 `principles.md`, 심각도·확신도 정의와 보고 규칙은 `severity.md`를 따릅니다. 각 영역 문서는 다른 영역 문서 없이 쓸 수 있게 독립적으로 작성했습니다.

## 확인 항목

- **프로젝트 규칙 문서:** AGENTS.md, CLAUDE.md, CONTRIBUTING 등에 명시된 규칙 위반(금지된 API, 파일 배치, 에러 처리 방식, 커밋·주석 언어)
- **린트·포맷 설정:** 설정에 있지만 린터가 실행되지 않는 범위(예: 설정에서 제외된 디렉터리 규칙), 설정 자체를 완화하는 변경(`eslint-disable` 남용, 규칙 끄기)
- **네이밍 컨벤션:** 프로젝트가 정한 대소문자·접두어·파일 이름 규칙
- **UI 일관성:** 디자인 시스템 컴포넌트·토큰 대신 임의 스타일, 문구 톤·용어 불일치, i18n 프로젝트의 하드코딩 문자열

## 판단 기준

- balanced에서는 프로젝트 설정(린트, 포맷, AGENTS.md, CLAUDE.md)을 **명확히 어긴** 경우만 보고하고, 근거에 해당 규칙의 위치를 인용합니다.
- 린터·포맷터가 기계적으로 잡는 문제(공백, 따옴표, import 순서)는 보고하지 않습니다.
- 사유 주석이 있는 의도적 `eslint-disable`은 보고하지 않습니다.
- 개인 취향에 따른 스타일 지적은 하지 않습니다.

## 심각도 예시

판단 기준을 맞추기 위한 예시입니다. 실제 심각도는 `severity.md` 1.1절의 요소로 조정합니다.

| 심각도 | 예시 |
|---|---|
| Critical | (해당 사례 원칙적으로 없음) 컨벤션 위반이 사고로 이어지면 그 결과 영역으로 보고. 예: AGENTS.md가 금지한 "운영 키를 코드에 넣기" → `security` Critical |
| Critical | (해당 사례 원칙적으로 없음) 예: CLAUDE.md가 금지한 "마이그레이션에서 `DROP` 사용" → `ops` 기준으로 판단 |
| High | AGENTS.md에 명시된 "모든 DB 접근은 repository 계층으로" 규칙을 어겨 감사 로그가 빠짐 (감사 누락이 핵심이면 `ops`·`security`) |
| High | i18n 필수 프로젝트에서 결제 화면 문구 전체를 하드코딩해 다국어 사용자에게 번역 없이 노출 |
| Medium | 프로젝트 규칙(CLAUDE.md)이 정한 에러 처리 헬퍼 대신 직접 `throw`해 응답 형식이 달라짐 |
| Medium | 디자인 시스템 버튼 대신 임의 스타일 버튼을 써서 화면 간 UI 불일치 |
| Low | 프로젝트 명명 규칙(파일명 kebab-case)과 다른 새 파일 이름 |
| Low | 사유 주석 없는 `eslint-disable` 한 줄 |

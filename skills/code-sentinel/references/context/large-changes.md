# 대형 변경과 partial

매니페스트 `split`이 `none`이 아니거나 `skipped`가 0보다 클 때, 또는 같은 치환이 수백 파일에 반복되는 기계적 대량 변경일 때 읽습니다. 보고서 형식은 `../report/partial.md`를 따릅니다.

**집계 기준**

- 파일 수와 줄 수는 규칙 제외를 뺀 값입니다(`target_files`, `target_lines`).
- 줄 수는 diff의 추가+삭제 줄 수이고, `--full`은 대상 파일의 전체 줄 수입니다.

**분할과 생략 (매니페스트 `split`)**

| 값 | 조건 | 모델의 처리 |
|---|---|---|
| `none` | 아래 기준 이하 | 전체를 한 번에 분석 |
| `recommended` | 대상 파일 60개 또는 3,000줄 초과 | 모듈(상위 디렉터리) 단위로 나눠 순서대로 분석 |
| `truncated` | 대상 파일 300개 또는 20,000줄 초과 | 위험 경로 우선으로 일부만 분석 가능. 분석하지 않은 파일이 있으면 partial |

- **위험 경로 우선순위:** 인증·인가·세션 → 결제·과금 → 개인정보 처리 → DB 마이그레이션·스키마 → 공개 API·이벤트 계약 → IAM·네트워크 정책·시크릿·CI 워크플로·Dockerfile → 설정·환경변수 → 나머지
- **기계적 대량 변경:** 같은 치환이 수백 파일에 반복되는 경우(이름 변경, 코드모드)는 패턴을 판별한 뒤 대표 샘플을 검토하고, 나머지는 패턴에서 벗어난 변경이 있는지 검사합니다. 실제 검토로 세는 것은 샘플뿐이고, 나머지는 "패턴 검사만 수행"으로 분류합니다.

**partial 판정**

실제로 검토하지 않은 대상 파일이 하나라도 있으면 상태는 `partial`입니다. 해당 사유:

- 크기 상한 초과(`size`, `total-size`)
- 필터 대상(`filter`, clean/process 필터 대상)
- 분량 때문에 생략
- 패턴 검사만 수행

수집된 파일을 실제 검토한 것으로 세지 않습니다. 보고서에는 전체 대상 파일 수, 실제 검토 파일 수, 검토 생략 파일 수와 목록(사유 포함), 규칙 제외 수, 상태, 분석 범위의 한계를 적고, 끝에 생략 파일을 이어서 검토할 `--files` 호출 예시를 넣습니다.

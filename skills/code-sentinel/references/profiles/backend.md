# backend 프로필

서버 코드, API, 데이터베이스 변경에서 "특히 확인할 것"을 8개 리뷰 영역에 덧붙이는 프로필입니다. 프로필은 영역을 대체하지 않습니다. 발견 항목은 아래 표시된 영역 slug로 보고하며, 해당 없는 항목은 보고서에 쓰지 않습니다. 심각도는 `../review/severity.md`, 보고 형식은 `../report/findings.md`를 따릅니다.

## 1. 감지 신호

변경 파일(`[FILES]`)의 경로·확장자와 저장소 manifest를 보고, 다음 중 하나라도 해당하면 적용합니다. frontend·infra 프로필과 동시에 적용될 수 있습니다.

| 종류 | 신호 |
|---|---|
| 서버 프레임워크 의존성 | `express`, `fastify`, `koa`, `@nestjs/*`, `hapi`, `django`, `flask`, `fastapi`, `starlette`, `rails`, `sinatra`, `spring-boot`, `gin`, `echo`, `fiber`, `chi`, `actix-web`, `axum`, `laravel`, `symfony`, `phoenix` |
| ORM·DB 클라이언트 | `prisma`, `typeorm`, `sequelize`, `knex`, `drizzle-orm`, `mongoose`, `sqlalchemy`, Django ORM, `activerecord`, `gorm`, `sqlx`, `ent`, `hibernate`·JPA, `diesel`, `pg`, `mysql2` |
| 마이그레이션·스키마 | `migrations/`, `db/migrate/`, `alembic/`, `*.sql`, `schema.prisma`, `*.migration.*` |
| API 라우트 | `routes/`, `controllers/`, `handlers/`, `api/`, `server/`, `pages/api/`, `app/**/route.ts`, `*.proto`, OpenAPI·GraphQL 스키마 |
| 큐·작업 | `jobs/`, `workers/`, `consumers/`, BullMQ·Celery·Sidekiq·Kafka·SQS 클라이언트 사용 |

신호가 하나도 없으면 적용하지 않습니다. 감지 근거(예: "`migrations/` 변경, `prisma` 의존성")는 보고서에 적지 않아도 되지만 적용 여부는 요약의 "적용 프로필"에 적습니다.

## 2. 영역별로 특히 확인할 것

### `security`

- **IDOR:** ID로 조회·수정·삭제하는 핸들러가 요청자와 리소스 소유자(또는 테넌트)를 비교하는지. 조회 쿼리 조건에 `user_id`·`tenant_id`가 들어가는지
- **SQL·명령 주입:** 쿼리 문자열 조립, ORM raw 쿼리에 입력 결합, `ORDER BY`·컬럼명처럼 바인딩할 수 없는 자리에 허용 목록 없이 입력 사용, 셸 명령 실행에 입력 결합
- **SSRF:** 웹훅·이미지 가져오기·URL 미리보기처럼 서버가 사용자 URL로 요청할 때 내부 주소(`127.0.0.1`, `169.254.169.254`, 사설 대역) 차단, 리다이렉트 추적 제한
- 대량 할당으로 권한·가격·소유자 필드 변경 가능, 인증 미들웨어가 새 라우트에 빠짐
- 에러 응답·로그에 쿼리, 스택, 토큰, 개인정보 노출

### `correctness`

- **경쟁 상태(확인 후 처리):** 잔액·재고·중복 가입 확인 후 쓰기를 트랜잭션·행 잠금·조건부 업데이트·유니크 제약 없이 수행
- **트랜잭션 경계:** 여러 테이블 쓰기가 한 트랜잭션에 묶이지 않음, 트랜잭션 밖에서 읽은 값으로 트랜잭션 안에서 결정
- **멱등성:** 재시도·중복 요청 시 이중 결제·이중 생성. 외부 결제·발송 API에 멱등키 전달 여부
- **큐·이벤트 중복 처리:** at-least-once 전달에서 같은 메시지를 두 번 처리해도 안전한지, 순서 역전 처리
- **예외를 삼키는 코드:** `catch` 후 성공 응답(200) 반환, 실패를 로그만 남기고 진행
- 마이그레이션과 코드의 정합성: 새 NOT NULL 컬럼을 기본값 없이 추가하고 바로 사용, 코드가 아직 없는 컬럼을 읽음

### `ops`

- **마이그레이션 하위 호환:** 구버전 코드와 새 스키마가 동시에 운영되는 배포 구간에서 깨지지 않는지(컬럼 삭제·이름 변경은 확장 → 이전 → 축소 단계로)
- **롤백 가능성:** down 마이그레이션 존재 여부, 롤백 시 데이터 유실
- **대형 테이블 락:** 큰 테이블에 대한 컬럼 추가(기본값 포함)·인덱스 생성·타입 변경이 쓰기를 막는지(`CONCURRENTLY`, 온라인 DDL 도구)
- **백필과 배포 순서:** 백필이 배포 전·후 어디서 실행돼야 하는지, 대량 백필의 배치 처리
- **재시도·타임아웃·백오프:** 외부 호출의 타임아웃, 지수 백오프와 지터, 재시도 대상 오류 구분
- **트랜잭션 안의 외부 호출:** 트랜잭션을 연 채 HTTP·결제·메시지 발행을 해 락을 오래 잡거나 롤백 후 외부 효과가 남음(아웃박스 패턴 고려)
- **상관 ID·구조화 로그:** 요청·작업 단위 추적 ID 전파, 로그 필드 구조화, 실패 경로의 로그·메트릭

### `architecture`

- **API 응답 계약 변경:** 필드 삭제·이름 변경·타입 변경, 에러 형식(코드·필드) 변경, 페이지네이션 방식 변경이 클라이언트를 깨뜨리는지. 버전·폐기 기간
- 이벤트·메시지 스키마 변경과 소비자 호환
- 핸들러에 비즈니스 로직·쿼리가 섞임, 서비스 계층 우회, 같은 테이블을 여러 모듈이 직접 수정

### `performance`

- **N+1 쿼리:** 목록을 가져온 뒤 루프 안에서 연관 데이터를 개별 조회(ORM lazy loading 포함). `include`·`JOIN`·`IN` 일괄 조회로 바꿀 수 있는지
- **인덱스:** 새 `WHERE`·`ORDER BY`·`JOIN` 조건에 맞는 인덱스, 외래 키 인덱스, 유니크 제약
- **락 범위:** `SELECT ... FOR UPDATE`의 범위가 필요 이상으로 넓음, 긴 트랜잭션
- **대량 데이터의 메모리 적재:** 전체 테이블·내보내기를 한 번에 메모리로(커서·스트리밍·배치 미사용)
- 루프 안 개별 INSERT·외부 API 호출

### `tests`

- 권한 거부(다른 사용자 리소스 접근) 테스트, 동시 요청·중복 요청 테스트, 마이그레이션 up/down 테스트
- 외부 결제·메시지 연동의 실패·타임아웃 경로 테스트
- 실제 DB·외부 서비스에 접속하는 테스트가 기본 테스트에 섞임

### `readability` · `style`

- 프로젝트의 에러 처리·응답 형식 규약, 로깅 규약(AGENTS.md 등)을 따르는지
- 마이그레이션 파일 이름·순번 규칙

## 3. 흔한 오탐 (보고하지 않음)

- 파라미터 바인딩된 쿼리(PostgreSQL식 번호 플레이스홀더, `?`, `:name` 바인딩, 쿼리 빌더)
- 의도와 범위가 맞는 정상적인 `SELECT ... FOR UPDATE`
- 유니크 제약이나 조건부 업데이트로 이미 보장된 동시성
- 프레임워크가 기본 제공하는 CSRF·이스케이프·타임아웃을 코드에서 확인한 경우
